# MINDLINK – Backend (Firebase)

Backend for MINDLINK, ALU Group 24. It uses **Firebase Authentication** for sign-in and **Cloud Firestore** to store data. The screens don't talk to Firebase directly. They use two interfaces, `AuthRepository` and `CheckInRepository`, and the Firebase versions of those are switched on in `lib/main.dart`.

## What's in it

| File | What it does |
|---|---|
| `lib/features/auth/data/firebase_auth_repository.dart` | Email/password sign-in and registration, Google sign-in, password reset, email verification, sign-out. Creates a `users` document for each new account. |
| `lib/features/auth/data/auth_error_messages.dart` | Turns Firebase error codes into short, polite messages. |
| `lib/features/check_in/data/firestore_check_in_repository.dart` | Create, read, update and delete check-ins. Reading uses live snapshots, so the UI updates instantly. |
| `lib/features/check_in/data/check_in_mapper.dart` | Converts check-ins to and from Firestore documents. |
| `firestore.rules` | Security rules: each student can only read and change their own data. |
| `firestore.indexes.json` | Composite index on `userId` + `createdAt` for the check-in list. |
| `lib/firebase_options.dart` | Generated by `flutterfire configure`. Connects the app to the Firebase project. |

## Database (Cloud Firestore)

**`users/{uid}`** – one document per student

| Field | Type | Notes |
|---|---|---|
| uid | string | Document id = Firebase Auth uid (primary key) |
| name | string | |
| email | string | |
| createdAt | timestamp | |

**`check_ins/{id}`** – one document per check-in

| Field | Type | Notes |
|---|---|---|
| id | string | Document id (primary key) |
| userId | string | Foreign key → `users.uid` |
| mood | string | great, good, okay, low, stressed |
| source | string | schoolwork, deadlines, relationships, family, money, health, other |
| helpType | string | calmDown, understand, talk, justTracking |
| note | string | Up to 200 characters |
| createdAt | timestamp | |

One user has many check-ins, linked through `userId`.

## Security rules (summary)

- Only signed-in users can read or write anything.
- A student can only read, update or delete check-ins whose `userId` is their own uid.
- New check-ins must have valid values for every field, and the note must be 200 characters or less.
- Updates can only change `mood` and `note`.
- A student can only read and write their own `users` document.

## Setup

1. Create a Firebase project and enable **Email/Password** and **Google** in **Authentication → Sign-in method**.
2. Create a **Firestore database** in production mode.
3. Connect the app:
   ```bash
   dart pub global activate flutterfire_cli
   flutterfire configure
   ```
   Choose the project, then **android** and **web**.
4. For Google sign-in on Android, add the debug SHA-1 in **Project settings → Your apps**:
   ```bash
   cd android
   ./gradlew signingReport      # Windows: .\gradlew.bat signingReport
   ```
5. Publish `firestore.rules` in **Firestore → Rules**, and create the index from `firestore.indexes.json` in **Firestore → Indexes**.
6. Run the app:
   ```bash
   flutter pub get
   flutter run
   ```

## Tests

The backend tests use `fake_cloud_firestore` and `firebase_auth_mocks`, so they run without internet:

```bash
flutter test test/unit
```

They cover error messages, the check-in mapper, full CRUD on the Firestore repository, and registration, sign-in and sign-out.
